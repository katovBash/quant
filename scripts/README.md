# Команды запуска

`scripts/` содержит только удобные команды для запуска нескольких шагов или открытия Terminal. Торговые правила лежат в `strategies/`, исследовательский код — в `experiments/` и `src/`, проверки — в `tests/`. Результаты хранятся в эксперименте или журнале счёта, а не здесь.

[`run_ema_snapshot.sh`](run_ema_snapshot.sh) повторяет прежний полный снимок EMA: запрашивает свечи, пересчитывает отчёты и запускает тесты. Он требует доступа к MOEX ISS и времени на расчёт. Для проверки только структуры каталога используйте `python3 -m src.catalog.check_ema_layout`; для бумажного пилота — команды в [`service/README.md`](../service/README.md).

`scripts/` — входные команды, а не место хранения стратегий, сигналов или результатов.

Для новых интервалов `fetch_minute_snapshot.py` загружает минутные свечи MOEX в локальный кэш; `check_minute_coverage.py` обновляет JSON доступности данных, `report_experiments.py` — [общий JSON статусов экспериментов](../experiments/status.json). Часовые свечи нельзя использовать как замену минутным для 15M и 30M.

[`papertrading_plzl.command`](papertrading_plzl.command) — запускаемый файл для macOS Terminal. При открытии завершает прежний фоновый экземпляр того же пилота и продолжает виртуальную торговлю в видимом окне с журналом `papertrading/live/PLZL/runner.log`. Не открывайте второй экземпляр одновременно; для остановки в окне нажмите Ctrl+C. Файл не создаёт реальные заявки.

[`papertrading_all.command`](papertrading_all.command) — открыть в Terminal живую tmux-сессию всех настроенных виртуальных счетов. `Ctrl+B`, затем `D` закрывает просмотр, оставляя процесс работать. Текущие ошибки источника и состояние счетов также видны в [`fleet_status.json`](../papertrading/live/fleet_status.json). Файл не создаёт реальные заявки.
