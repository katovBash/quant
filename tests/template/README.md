# Шаблон проверок для новой идеи

Тесты отвечают на вопрос **«верно ли реализовано правило?»**, а `experiments/.../results/` — на вопрос **«что получилось на истории?»**. Доходность, win rate и число сделок нельзя заменить тестом кода.

## 1. До полного перебора — новый индикатор или паттерн

В README эксперимента перечислить конкретные пути тестов и команду запуска. Проверки обязательны для **нового алгоритма**, а не для каждого тикера и каждого значения параметра:

| Проверка | Что показать на маленьких искусственных свечах |
| --- | --- |
| Формула | Известные или вручную проверенные значения, прогрев, плоский рынок, крайние случаи |
| Причинность | Добавленная будущая свеча не меняет уже рассчитанные прошлые сигналы; опорная точка доступна только после подтверждения |
| Событие входа/выхода | Сигнал возникает на закрытой свече, а не на незавершённой; противоположный сигнал закрывает/разворачивает позицию по записанному правилу |
| Исполнение | Цена следующей свечи, комиссия, проскальзывание, размер и допустимые направления влияют на результат ожидаемым образом |
| Пробный запуск | Два тикера и один интервал создают полный CSV с базовым сравнением и явной записью ошибок данных |

Если индикатор уже реализован, повторно не пишем идентичный тест. Даём ссылку на существующий тест и добавляем только проверку нового правила или параметра, которого он не покрывает.

## 2. Перед переносом в `strategies/`

- Для **одной зафиксированной настройки** сравнить Python-сигнал с расчётом выбранной строки эксперимента на одинаковых свечах.
- Проверить long, short, отсутствие сигнала и прогрев; отдельная ручная сверка дат сделок в TradingView для Pine.
- Скрипт переноса проверяет, что в стратегии есть README, `strategy.py` и `strategy.pine`; наличие файлов не означает подключения к paper trading.

## 3. Перед paper trading

Тесты сервиса проверяют повторный опрос без двойной сделки, сохранение и восстановление состояния, пропуски свечей, ошибку источника без заявки, капитал/лот/расходы и соответствие версии Python-правила выбранной стратегии. Затем один запуск `--once` на сохранённых свечах без сети. Виртуальный счёт подключаем **после отдельного согласия пользователя**.

## Имена и запуск

`tests/indicators/test_<индикатор>.py` — формула; `tests/experiments/test_<эксперимент>.py` — сигнал и исследовательский бэктест; `tests/strategies/test_<стратегия>.py` — зафиксированное правило; `tests/service/` — виртуальное исполнение. Старые тесты EMA остаются в `tests/ema/` до переразмещения. Из корня проекта:

```bash
python3 -m unittest discover -s tests -t . -v
```

В README каждого эксперимента записать результат последнего запуска тестов и дату. **Не начинать полный перебор**, если новый расчёт не прошёл проверки формулы, причинности и малого прогона.
