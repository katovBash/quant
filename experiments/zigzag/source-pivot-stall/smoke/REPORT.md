Все пары, включая убыточные и правила с несколькими удачными месяцами, есть в [таблице пар](monthly_case_summary.csv). Исходные [месяцы](monthly_returns.csv) и [разбивка по фазам](monthly_regime_profiles.csv) сохранены отдельно. Если фазы рынка размечены после завершения месяца, их нельзя использовать как сигнал того же месяца.

Неполный последний месяц не включён в годовой итог. Доходность одной пары не равна доходности общего портфеля. Если модель расходов `gross_before_costs`, результат до комиссии, спреда, проскальзывания, дивидендов и стоимости short. История уже просмотрена при выборе гипотезы; статус `REVIEW_ONLY`.

## Long и short по отдельности

Разбивка закрытых сделок по направлениям пока не рассчитана. Вывод о long или short не делается; нужен журнал сделок с полем `side` и отдельный пересчёт вариантов только long и только short.


## Исходный ZigZag и момент входа

Использованы исходные `add_pivots` и `draw_zigzag` из присланного Pine, а также правила `ta/1` для sticky Bollinger Bands; Python переносит их **настройки по умолчанию**. Указанный на графике конец плеча предварительный и может передвинуться. Вход происходит ровно через выбранные 0–30 закрытых свечей после последнего экстремума: низ → long, верх → short. Новый экстремум сбрасывает счётчик; сигнал исполняется на открытии следующей свечи. Выход — только при противоположном таком сигнале.

[Проверочные события для задержек 5/10/30](entry_trace.csv) показывают дату экстремума, дату сигнала и первую возможную цену исполнения. 15M/30M в этом снимке имеют `SOURCE_MISSING`, потому что минутных свечей нет. Pine ещё не сверен по сделкам с Python на данных TradingView; результаты не разрешают paper trading.
