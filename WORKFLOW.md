# Путь гипотезы: эксперимент → стратегия → paper trading

Папки обозначают **этап работы**, а не оценку будущей прибыли. Исторические проценты после перебора — повод проверить правило, а не доказательство преимущества.

| Шаг | Что делаем | Что сохраняем | Проверка перед следующим шагом |
| --- | --- | --- | --- |
| 1. Заводим эксперимент | Фиксируем гипотезу, источник и снимок данных, тикеры, интервалы, диапазоны параметров, контроль, издержки и разделение истории **до перебора** | `experiments/<имя>/README.md` по [шаблону](experiments/template/README.md) | Другой человек может воспроизвести тот же набор вариантов |
| 2. Пишем расчёт | Индикатор и бэктест в `src/` или в эксперименте; точка запуска — `experiments/<имя>/run.py` | Код и команда запуска в README | Тест формулы на известных примерах, тест без будущих свечей, тест момента исполнения и расходов; один малый пробный запуск |
| 3. Запускаем полный перебор | Считаем все запланированные пары «тикер × интервал × параметры», в том числе убытки и ошибки источника | `results/` с полными таблицами и обязательными `REPORT.md`, `monthly_case_summary.csv`: прибыльные месяцы, средняя месячная доходность, средний плюс и минус, худший месяц, расходы и контроль | Сверены число ожидаемых и полученных рядов, пропуски не скрыты; отчёт создан после каждого завершённого прогона, результата одной лучшей строки недостаточно |
| 4. Фиксируем кандидата | Ищем устойчивую область соседних параметров, проверяем ту же настройку на заранее названных других бумагах и периоде, сравниваем с контролем и расходами; отдельно проверяем чистую доходность каждого полного месяца | Решение в README, `candidate.json`, Python- и Pine-код только для выбранного правила | [Исторический критерий](criteria/README.md), отсутствие убыточных и нулевых месяцев по новой цели, явная область применения и пометка `seen_history`/`unseen_holdout` |
| 5. Создаём стратегию | [Скрипт переноса](criteria/README.md) копирует только фиксированное правило; ручной кандидат помечаем как предварительный, пока проверки не закончены | `strategies/<имя>/README.md`, `strategy.pine`, `strategy.py`, `robustness.json`; исходные таблицы остаются в эксперименте | По каждому выбранному тикеру проверить долю прибыльных месяцев, худший месячный PnL, число сделок и просадку; окна по 100 сделок остаются дополнительной диагностикой. Пользователь вручную сверяет сделки в TradingView, расхождения и стоимость short документируются |
| 6. Подключаем paper trading | **Только после отдельного решения пользователя** регистрируем проверенный Python-сигнал и пару «правило × тикер × интервал» в сервисе | конфигурация и новый журнал в `papertrading/live/` | Тест совпадения сигналов с выбранным правилом, повторного запуска, пропусков свечей, ошибок источника и расходов; затем пробный `--once` |
| 7. Оцениваем новые сделки | Не меняем правило задним числом; сравниваем виртуальный счёт с заранее выбранным контролем | Сделки, капитал, [месячная категория](papertrading/live/STATUS.md) и отчёт [оценщика](criteria/README.md) | Через 30 календарных дней положительный виртуальный результат после подтверждённых расходов даёт только `APPROVED_30D_PAPER`; исследовательское свидетельство преимущества оцениваем отдельно; при изменении правила начинаем новую версию |

## Когда нужны тесты и скрипты

- **Тесты нужны для нового расчётного поведения**, даже если это ещё эксперимент. [Шаблон тестов](tests/template/README.md) требует проверку формулы, причинности и малого прогона до массового расчёта; при новой стратегии добавляем тест точного сигнала, а при подключении paper trading — тесты исполнения и сохранения состояния. Тесты проверяют правильность реализации, не прибыльность.
- **`run.py` внутри эксперимента** нужен, когда расчёт должен воспроизводиться. Он пишет в `results/`. Для одного только описания идеи исполняемый файл не создаём и статус ставим `запланирован`.
- **`scripts/`** содержит лишь удобные команды запуска нескольких шагов или Terminal. Для каждого эксперимента новый файл там не требуется. Торговое правило никогда не берётся из `scripts/`.
- **Python и Pine** обязательны для каждой выбранной стратегии. Pine нужен для ручной сверки в TradingView; Python задаёт тот же сигнал и до подключения к сервису не исполняется автоматически. Сервис Pine не читает.

Текущий [EMA Grid Search](experiments/ema-grid-search/README.md) прошёл полный исторический перебор. Самостоятельные результаты перечислены в [каталоге одного индикатора](experiments/single-indicator/README.md); из завершённых расчётов отдельные фиксированные правила могут попасть в стратегии для ручной проверки. [Каталог сочетаний](experiments/double-indicator/README.md) содержит первое сравнение SMA с фильтрами боковика и план других пар; [протокол сравнения](experiments/INDICATOR_RELATIONSHIPS.md) требует отделять результаты сочетания от одиночного правила. [Виртуальные счета](papertrading/README.md) не меняются из-за появления нового исторического максимума.
