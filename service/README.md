# Локальный сервис бумажной торговли

Для нескольких правил служит [`paper_fleet.py`](paper_fleet.py): он читает [отдельные setup каждого счёта](../papertrading/setups/fleet/), обновляет свечи MOEX один раз на тикер за цикл, запускает только зарегистрированный Python-сигнал и пишет каждому правилу собственный журнал. [`paper_runner.py`](paper_runner.py) по-прежнему поддерживает прежний одиночный счёт PLZL. Pine сервис не исполняет. Fleet не создаёт брокерские или TradingView-заявки.

Запуск всех настроенных виртуальных счетов: `python3 -u -m service.paper_fleet --poll-seconds 900`. Один опрос и выход: та же команда с `--once`. Состояние и ошибки по каждому счёту — в [`fleet_status.json`](../papertrading/live/fleet_status.json) после запуска, полный поток — в [`fleet.log`](../papertrading/live/fleet.log). При недоступности MOEX статус `DATA_UNAVAILABLE` означает, что журнал сделок не менялся; процесс попробует снова через 15 минут. Повторный экземпляр fleet отклоняется блокировкой.

Для новых правил нужны завершённые свечи с OHLC, отдельный setup, тест сигнала и сравнение с Pine. Для 4H используются блоки часовых свечей по торговому дню, как в исследовании; текущий неполный блок не участвует в сигналах. Существующий одиночный счёт PLZL не переключается и продолжает хранить свою прежнюю конфигурацию.

[`paper_runner.py`](paper_runner.py) также может исполнить один setup за раз. Он получает завершённые свечи из MOEX ISS, загружает Python-правило из папки стратегии и ведёт собственную виртуальную книгу. [Pine для EMA12/33](../strategies/ema-cross-12-33-long-short-1h/strategy.pine) предназначен для TradingView и сервисом не исполняется. Реальные заявки и заявки в TradingView сервис не отправляет.

Получение и проверка свечей вынесены в [`data_sources/moex.py`](data_sources/moex.py). Это текущий источник данных; [брокерских подключений](brokers/README.md) нет. Чтобы заменить MOEX на другой источник, нужен адаптер к тому же формату завершённых свечей и отдельная сверка времени, цен и полноты истории. `paper_runner.py` пока явно вызывает адаптер MOEX, выбор источника через настройку ещё не реализован.

Сигнал и нужная сторона позиции определяются в `strategy.py`; момент виртуального исполнения, размер позиции, лот, издержки, журнал и защита от пропущенных свечей — в `paper_runner.py`. Новые стратегии нужно отдельно реализовать на Python и проверить совпадение сигналов с Pine. Редактирование правил уже запущенного процесса не обновляет его автоматически: после сверки нужен контролируемый перезапуск.

## Запуск

Для нового счёта используйте [setup отдельной пары](../papertrading/README.md). Он фиксирует капитал, долю позиции, лот и расходы; исполнитель откажется продолжать счёт, если конфигурация после старта изменилась. Пример новой версии PLZL с лимитом 10% (создаёт отдельный журнал, не запускайте одновременно со старым счётом без отдельной проверки общего капитала):

```bash
python3 -m service.paper_runner --setup papertrading/setups/plzl-ema12-33-1h-10pct.json --once
```

Указанный в setup стоп пока выключен; ненулевое значение вызовет ошибку, потому что виртуальное исполнение стопа ещё не реализовано и не проверено.

Для просмотра всех счетов в macOS откройте [`scripts/papertrading_all.command`](../scripts/papertrading_all.command): он присоединяет Terminal к работающей tmux-сессии. `Ctrl+B`, затем `D` закрывает только просмотр. Прежний одиночный пилот PLZL можно открыть через [`scripts/papertrading_plzl.command`](../scripts/papertrading_plzl.command). Автозапуска после перезагрузки Mac нет.

Из корня репозитория, для **одного** тикера после сверки размера лота. Пилот из [paper trading](../papertrading/README.md) подготовлен для PLZL 1H:

```bash
python3 -m service.paper_runner --symbol PLZL --lot-size 1 --mode long_short --once
python3 -m service.paper_runner --symbol PLZL --lot-size 1 --mode long_short --poll-seconds 900
```

`--once` получает текущий срез и завершает работу. Без него процесс остаётся запущенным и опрашивает источник каждые 15 минут. Первый запуск **только создаёт состояние** по уже доступной истории: старые сигналы не превращаются в новые сделки. После появления новых завершённых свечей сервис записывает сигнал и исполняет виртуальную заявку на **закрытии следующей наблюдаемой завершённой свечи**. Это более позднее исполнение, чем в Pine Strategy Tester, и его нельзя напрямую сравнивать с прежним бэктестом «следующее открытие».

В ответе каждой проверки сервис явно показывает `strategy`, начальный капитал, долю позиции, размер лота, комиссию, проскальзывание и предполагаемую годовую стоимость займа. Те же значения фиксируются в `state.json` и не могут быть незаметно изменены после начала наблюдения.

`--lot-size` нужно брать из актуальных параметров инструмента, а не копировать пример. Для PLZL на TQBR [ответ MOEX ISS](https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities/PLZL.json?iss.meta=off&iss.only=securities) на 01.11.2026 содержит `LOTSIZE=1`, `MINSTEP=0.2` ₽. По умолчанию комиссия 5 б.п. за сторону, проскальзывание 10 б.п. **в процентах цены, не один тик**, и ставка займа short 0; перед содержательной проверкой short нужно указать действующую ставку через `--borrow-bps-annual` и отдельно учитывать дивиденды. Изменять параметры уже запущенного счёта нельзя: сервис отклонит конфигурацию. Для другого правила или тикера создайте отдельное состояние.

Для проверки механики без сети можно подать JSON сохранённого скана:

```bash
python3 -m service.paper_runner --symbol PLZL --lot-size 1 --once \
  --replay data/moex_scan/PLZL_60_2024-01-01_2026-10-30.json \
  --output /tmp/quant-paper-demo
```

Сервис сохраняет `state.json` как источник истины и восстанавливает производные `trades.csv`, `equity_observations.csv`, `equity.csv` и `closed_trades.csv`. Последние два файла можно передать [оценщику](../criteria/README.md), указав в `--frozen-on` **календарный день перед первым запуском**; старые сигналы всё равно не попадают в журнал. Если между опросами пропущено больше одной завершённой свечи, сервис не исполняет старый сигнал задним числом: фиксирует `GAP`, отменяет ожидавшую заявку и ждёт следующего сигнала. Fleet обновляет общий кэш свечей один раз на тикер за цикл.

## Границы текущей версии

- Fleet работает в отдельной tmux-сессии, но не настроен как служба macOS и не продолжает работу при выключенном компьютере.
- Встроенный Paper Trading TradingView от Pine не получает автоматических заявок; здесь отдельная виртуальная книга. [Порядок сверки](PAPERTRADING_WORKFLOW.md).
- В логе `OK` означает успешный опрос MOEX, даже если новых сигналов нет. `DATA_UNAVAILABLE` означает, что свечи не удалось получить; виртуальная заявка не создаётся, следующий опрос будет через `retry_after_seconds`. `PROCESSING_ERROR` означает другую ошибку обработки или записи. После изменения кода уже запущенный процесс нужно перезапустить, чтобы увидеть новые статусы.
- `equity.csv` и `closed_trades.csv` формируются автоматически, но подтверждение расходов для [оценщика](../criteria/README.md) остаётся ручной проверкой. Если short активен, нельзя считать нулевую цену займа подтверждённой.
- Корпоративные события, выплаты по короткой позиции и фактическая доступность short пока не моделируются. Не присваивайте статус подтверждённого преимущества на основании этого журнала.
- Не распространяйте рыночные данные вместе с кодом без проверки [условий MOEX ISS](https://www.moex.com/a2193).

Текущие 12 счетов имеют отдельный виртуальный капитал по 1 млн ₽. Общий портфель с ограничением суммарного риска, проверка живых лотов и фактических short-расходов пока не реализованы; поэтому их доходности нельзя складывать как результат одного счёта.
